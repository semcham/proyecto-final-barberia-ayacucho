# 05. Restricciones

Una restricción es una condición **no negociable** que limita las decisiones. Cada una indica cómo condiciona el diseño.

| ID   | Tipo                | Restricción                                             | Descripción                                                                                                                                                                                                        | Cómo condiciona la decisión                                                                                                                                   |
| ---- | ------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| RC01 | Tecnológica         | Aplicación solo web                                     | La plataforma se usa desde navegador (responsive). No hay app móvil nativa; queda como evolución futura                                                                                                            | No se diseñan contenedores ni componentes móviles. Interfaz web adaptable (ADR-001, [tecnologías](../02-arquitectura-software/tecnologias.md))                |
| RC02 | Organizacional      | Git y GitHub                                            | Repositorio versionado, ramas y commits convencionales                                                                                                                                                             | Documentación en Markdown y diagramas en Mermaid dentro del repositorio                                                                                       |
| RC03 | Tecnológica         | Comunicación por API REST                               | Frontend y backend se comunican por API REST sobre HTTPS                                                                                                                                                           | Backend sin estado; contratos HTTP documentados; CORS (ADR-006, ADR-010)                                                                                      |
| RC04 | Tecnológica         | PostgreSQL como base principal                          | Datos transaccionales en PostgreSQL                                                                                                                                                                                | Aprovecha restricciones de exclusión y RLS (ADR-004, ADR-009)                                                                                                 |
| RC05 | Tecnológica         | Pasarela de pago externa                                | El procesamiento de pagos lo realiza un proveedor externo                                                                                                                                                          | Módulo de pagos desacoplado con puerto `PaymentGateway` (ADR-007); hoy, con una pasarela simulada (ADR-022)                                                   |
| RC06 | Del proyecto        | Presupuesto y recursos del equipo                       | Equipo universitario sin presupuesto significativo; infraestructura inicial reducida                                                                                                                               | Monolito modular; sin microservicios; en la nube, una instancia al inicio (ADR-001, ADR-006); en local, dos réplicas solo para demostrar el escalado (ADR-030) |
| RC07 | Del proyecto        | Calendario del curso                                    | El primer sprint es documentación completa; no se exige implementación                                                                                                                                             | Los sprints 1 y 2 son el entregable de documentación; la implementación sigue el plan de entrega por funcionalidades ([backlog y plan](../05-gestion/02-backlog-y-sprints.md)) |
| RC08 | Legal               | Protección de datos personales                          | Ley N.° 29733 y D. S. N.° 016-2024-JUS (vigente desde 30-03-2025 según fuentes secundarias; verificar en _El Peruano_)                                                                                             | Consentimiento, minimización, respaldos, auditoría, procedimiento de incidentes (ADR-010, [seguridad](../02-arquitectura-software/seguridad-y-privacidad.md)) |
| RC09 | Organizacional      | Marco del curso                                         | Seguir Guías 02, 03 y 04: proceso necesidades → decisiones; C4, UML y ADR                                                                                                                                          | Estructura de `docs/` y trazabilidad obligatoria                                                                                                              |
| RC10 | Organizacional      | Estilo y enfoque dados por el curso                     | Monolito modular, cuatro capas con Clean Architecture                                                                                                                                                              | ADR-001, ADR-002, ADR-011                                                                                                                                     |
| RC11 | Tecnológica         | IA por API externa                                      | No se exige entrenar un modelo propio; se consume un proveedor por API                                                                                                                                             | Puerto `AIProvider`; costos y latencia variables; degradación controlada (ADR-008, ADR-012)                                                                   |
| RC12 | Legal / seguridad   | Sin datos de tarjeta en la plataforma                   | Con API directa el comercio asume PCI DSS; con Checkout los datos no pasan por sus servidores (Culqi, D-06)                                                                                                        | Se usa el flujo alojado por el proveedor; no se almacenan PAN ni CVV (ADR-007)                                                                                |
| RC13 | Del proyecto        | Distinguir arquitectura objetivo de implementación real | Lo diseñado no es lo construido                                                                                                                                                                                    | Etiquetas implementado / prototipado / planificado / futuro en todos los documentos                                                                           |
| RC14 | Del proyecto        | Experiencia limitada del equipo                         | Curva de aprendizaje de tecnologías nuevas                                                                                                                                                                         | Tecnologías con documentación abundante; abstracciones solo donde hay riesgo de cambio (ADR-011)                                                              |
| RC15 | Contextual          | Conectividad variable                                   | A nivel nacional el uso de Internet es menor en zonas rurales (56,1 %, D-01); la situación en Ayacucho está **por validar**                                                                                        | Respuestas livianas, interfaz tolerante a reintentos, sin dependencia de anchos de banda altos                                                                |
| RC16 | Tecnológica / legal | Mensajería por WhatsApp mediante proveedor              | Se requiere un proveedor oficial o intermediario de la WhatsApp Business Platform; condiciones como consentimiento previo, plantillas de mensaje aprobadas y costos **por verificar con su documentación oficial** | Puerto `NotificationChannel` con un adaptador `WhatsAppSender`, correo como respaldo, consentimiento registrado (ADR-013; planificado, funcionalidad 004)     |

> Las restricciones RC01, RC03, RC04, RC05 y RC08 provienen del encargo; RC09 y RC10 del curso; las demás son del proyecto o del contexto.
